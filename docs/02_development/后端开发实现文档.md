## 一、模块说明

### 1.1 本次实现的模块范围

本次实现 **M09 推荐场景编排模块**，对应任务拆解文档 M09-T01 ~ M09-T04 共 4 个任务，是推荐引擎的对外 API 核心入口。

| 任务ID | 任务名称 | 实现状态 | 对应类 |
|-------|---------|---------|-------|
| M09-T01 | RecommendationFacade 推荐门面 | ✅ 已实现 | `service/RecommendationFacade.java` |
| M09-T02 | 4 种场景策略实现 | ✅ 已实现 | `service/scene/`（Home/Guess/Related/Search + 工厂） |
| M09-T03 | 推荐结果缓存（分层 TTL + 热点预缓存） | ✅ 已实现 | `service/cache/RecommendCacheService.java` |
| M09-T04 | 推荐与行为 Controller | ✅ 已实现 | `controller/`（4 个 Controller） |

**推荐主链路编排流程**（架构文档 M09-T01）：

```
请求进入 → A/B 分流(MurmurHash3) → 缓存检查 → 场景策略选择
    → 多路召回(200~300候选) → 特征组装 → 精排(三级降级) → 重排(类目打散+长尾加权)
    → 缓存写入 → 曝光埋点 → 返回统一响应
```

本次实现复用了架构文档 M01（工程骨架）和 M02（API 定义）中的公共组件：

## 二、核心代码实现

### 2.1 推荐门面（RecommendationFacade）

**文件路径**：`src/main/java/com/example/recommend/service/RecommendationFacade.java`

**功能**：编排推荐主链路全流程，各阶段计时埋点，异常处理与降级。

**核心方法**：

```java
public RecommendResponseDTO recommend(RecommendRequestDTO request)
```

**入参**：
- `RecommendRequestDTO`：推荐请求（scene/userId/itemId/keyword/pageSize/device）

**出参**：
- `RecommendResponseDTO`：推荐响应（scene/abGroup/modelVersion/items/candidateCount/duration）

**关键逻辑**：

1. **场景策略选择与校验**：通过 `SceneStrategyFactory` 获取策略，调用 `validate()` 校验场景特定参数（如 related 需 itemId）
2. **A/B 分流**：`MurmurHash3(userId + ":" + experimentId) % 100`，50% control / 50% experiment
3. **缓存检查**：Key = `rec:result:{scene}:{userId}:{abGroup}:{modelVersion}`，命中直接返回（< 5ms）
4. **多路召回**：委托场景策略执行召回，返回 200~300 候选
5. **召回为空处理**：返回空列表，code=400001（HTTP 200，非错误）
6. **精排+重排**：调用 `RankService.rank()`，含三级降级（DeepFM→XGBoost→规则）
7. **场景后处理**：调用 `SceneStrategy.postProcess()`
8. **缓存写入**：根据用户活跃度自动选择分层 TTL（高频 10s / 普通 60s / 兜底 120s）
9. **曝光埋点**：异步发送 impression 事件

**注意事项**：
- 缓存写入和曝光埋点均为异步，不阻塞响应
- 各阶段耗时记录在 `DurationDetail` 中，用于性能分析
- 召回为空不抛异常，返回空列表（架构文档 400001 错误码定义）

### 2.2 场景策略（SceneStrategy + 4 实现 + 工厂）

**文件路径**：`src/main/java/com/example/recommend/service/scene/`

**接口定义**：

```java
public interface SceneStrategy {
    Scene getScene();
    List<CandidateItem> recall(RecommendRequestDTO request);
    default List<RankedItem> postProcess(List<RankedItem> items, RecommendRequestDTO request);
    default void validate(RecommendRequestDTO request);
}
```

**4 种场景实现**：

| 场景 | 实现类 | 召回通道组合 | 必填参数 |
|-----|-------|------------|---------|
| home | `HomeStrategy` | ItemCF + 标签 + 画像 + 热门 | userId |
| guess | `GuessStrategy` | ItemCF + 标签 + 画像 + 热门 | userId |
| related | `RelatedStrategy` | ItemCF + 标签 + ES 文本 | itemId |
| search | `SearchStrategy` | ES 文本 + ES 语义 + 热门 | keyword |

**场景策略工厂**（`SceneStrategyFactory`）：
- 构造函数自动注入所有 `SceneStrategy` 实现，按场景注册到 `EnumMap`
- 新增场景只需实现接口并标注 `@Component`，工厂自动发现（开闭原则）
- 不支持的场景抛出 `BusinessException(SCENE_NOT_SUPPORTED)`

### 2.3 推荐结果缓存（RecommendCacheService）

**文件路径**：`src/main/java/com/example/recommend/service/cache/RecommendCacheService.java`

**功能**：分层 TTL 缓存，热点预缓存，行为触发失效。

**核心方法**：

| 方法 | 说明 |
|-----|------|
| `buildKey(scene, userId, abGroup, modelVersion)` | 构建缓存 Key |
| `get(key)` | 获取缓存，过期自动清除 |
| `put(key, value, userId)` | 写入缓存，自动选择分层 TTL |
| `invalidateByUser(userId)` | 按用户失效缓存（行为上报触发） |
| `invalidateByPrefix(prefix)` | 按前缀批量失效（管理后台使用） |
| `recordAccess(userId)` | 记录用户访问（高频判定） |

**分层 TTL 策略**（架构文档 6.5 节）：

| 用户类型 | 判定条件 | TTL | 说明 |
|---------|---------|-----|------|
| 高频用户 | 近 5 分钟访问 > 10 次 | 10s | 对实时特征友好（P2-03） |
| 普通用户 | 有访问记录 | 60s | 平衡实时性与命中率 |
| 兜底用户 | 无行为数据 | 120s | 减少计算压力 |

**防雪崩**：TTL 加随机偏移 ±10s，避免大量 Key 同时过期。

**实现方式**：`ConcurrentHashMap<String, CacheEntry>` + 过期时间戳，未安装 Redis 时也可运行。生产环境由 M03 的 `RedisService` 替换。

**路径**：`GET /api/v1/user/{userId}/profile`

#### 2.4.4 热门物品接口（HotItemsController）

**路径**：`GET /api/v1/hot/items`

### 2.5 公共组件

#### 2.5.1 统一响应（Result<T>）

所有接口返回统一结构：

```json
{
  "code": 0,
  "message": "success",
  "traceId": "abc-123-def",
  "timestamp": 1727937000123,
  "data": { ... }
}
```

静态工厂方法：`success()` / `success(data)` / `fail(errorCode)` / `degraded(errorCode, data)`

#### 2.5.2 错误码枚举（ErrorCode）

25+ 错误码，6 位数字编码（前 2 位模块 + 后 4 位序号），每个错误码关联 HTTP 状态码。详见第三章接口定义。

#### 2.5.3 全局异常处理器（GlobalExceptionHandler）

捕获以下异常并统一转换：

| 异常类型 | 错误码 | HTTP 状态 |
|---------|-------|----------|
| `BusinessException` | 携带的错误码 | 错误码关联的状态 |
| `MethodArgumentNotValidException` | 100001 | 400 |
| `MissingServletRequestParameterException` | 100002 | 400 |
| `MethodArgumentTypeMismatchException` | 100003 | 400 |
| `RequestNotPermitted`（限流） | 600001 | 429 |
| `Exception`（兜底） | 500001 | 500 |

#### 2.5.4 TraceId 过滤器（TraceIdFilter）

- 优先透传上游 `X-Trace-Id`，不存在则生成 UUID
- 写入 MDC（`traceId`），Logback 模板中通过 `%X{traceId}` 输出
- 响应头回传 `X-Trace-Id`
- 请求结束后清理 MDC，避免线程池复用污染

## 三、接口定义

### 3.1 统一响应格式

所有接口返回 `Result<T>` 结构：

| 字段 | 类型 | 说明 |
|-----|------|------|
| code | int | 业务状态码，0=成功，非0=错误（见 3.3 错误码） |
| message | string | 状态描述 |
| traceId | string | 全链路追踪 ID |
| timestamp | long | 服务端响应时间戳（毫秒） |
| data | object | 业务数据，错误时为 null |

### 3.2 核心接口清单

#### 3.2.1 推荐接口

**GET /api/v1/recommend**

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| scene | string | 是 | 场景：home / guess / related / search |
| userId | string | 是 | 用户 ID |
| itemId | string | related 必填 | 相关推荐的参考物品 ID |
| keyword | string | search 必填 | 搜索关键词 |
| pageSize | int | 否 | 返回数量，默认 20，最大 50 |
| device | string | 否 | 设备类型：mobile/pc/web，默认 web |

**响应 data 结构**（`RecommendResponseDTO`）：

| 字段 | 类型 | 说明 |
|-----|------|------|
| scene | string | 推荐场景 |
| abGroup | string | A/B 实验组（control/experiment） |
| modelVersion | string | 实际使用的模型版本 |
| items | array | 推荐物品列表 |
| candidateCount | int | 召回候选数量 |
| duration | object | 各阶段耗时明细（毫秒） |

**物品结构**（`RecommendItemDTO`）：

| 字段 | 类型 | 说明 |
|-----|------|------|
| itemId | string | 物品 ID |
| rank | int | 排名（从 1 开始） |
| score | double | 推荐分数 |
| recallChannel | array | 召回通道（itemcf/tag/profile/hot/es_text/es_semantic） |
| item | object | 物品详情（itemId/name/description/categoryId/price/tags/status/hotScore） |

#### 3.2.2 行为采集接口

**POST /api/v1/behavior**

**请求体**（`BehaviorEventDTO`）：

| 字段 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| userId | string | 是 | 用户 ID |
| itemId | string | 是 | 物品 ID |
| actionType | string | 是 | 行为类型：click/view/favorite/impression/conversion |
| scene | string | 是 | 场景 |
| eventTime | string | 是 | 事件发生时间（ISO 8601） |
| extra | object | 否 | 扩展字段 |

**响应 data**：`{"accepted": true, "eventId": "abc123"}`

> eventId 由服务端生成：`MurmurHash3(userId + itemId + actionType + eventTime)`，异步写入 Kafka，立即返回。

#### 3.2.3 用户画像查询接口

**GET /api/v1/user/{userId}/profile**

**路径参数**：`userId` - 用户 ID

**响应 data**（`UserProfileDTO`）：

| 字段 | 类型 | 说明 |
|-----|------|------|
| userId | string | 用户 ID |
| longTerm | object | 长期画像（类目偏好/标签权重/活跃度/活跃时段/价格偏好） |
| shortTerm | object | 短期画像（近期点击/收藏/类目/行为数） |
| fusedTags | object | 融合标签权重（短期 0.6 / 长期 0.4） |
| version | long | 画像版本号 |
| updatedAt | long | 最后更新时间 |

#### 3.2.4 热门物品接口

**GET /api/v1/hot/items**

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| categoryId | int | 否 | 类目 ID，不传则返回全局热门 |
| limit | int | 否 | 返回数量，默认 20，最大 100 |

**响应 data**：`HotItemDTO[]`，含 itemId/rank/hotScore/clickCount/favoriteCount/item

#### 3.2.5 健康检查与指标（Actuator）

| 接口 | 说明 |
|-----|------|
| `GET /actuator/health` | 健康检查（含磁盘/数据库等组件状态） |
| `GET /actuator/prometheus` | Prometheus 格式指标 |

### 8.1 严格遵循架构设计的要点

| 架构要求 | 实现方式 | 对应章节 |
|---------|---------|---------|
| 统一响应格式 | `Result<T>` 含 code/message/traceId/timestamp/data | 架构 5.1 |
| 6 位错误码 | `ErrorCode` 枚举 25+ 错误码，前 2 位模块 + 后 4 位序号 | 架构 5.2 |
| 4 种推荐场景 | Home/Guess/Related/Search 策略 + 工厂 | 架构 5.4.1 |
| A/B MurmurHash3 分流 | `MurmurHash3(userId:experimentId) % 100` | 架构 3.5 |
| 分层 TTL 缓存 | 高频 10s / 普通 60s / 兜底 120s + 随机偏移 | 架构 6.5 |
| 三级降级链 | DeepFM → XGBoost → 规则（RankService 接口定义） | 架构 2.4.5 |
| Resilience4j 限流 | 推荐 1000 / 行为 2000 / 搜索 500 QPS | 架构 M01-T06 |
| TraceId 全链路 | Filter 生成/透传 + MDC + 响应头 | 架构 M01-T05 |
| 虚拟线程 | `spring.threads.virtual.enabled=true` | 架构 M01-T01 |
| 配置外部化 | `RecommendProperties` 绑定 `recommend.*`，无魔法数字 | 架构 M01-T02 |
| 曝光埋点异步 | 推荐返回后异步发送 impression 事件 | 架构 M08-T04 |
| eventId 生成 | MurmurHash3(userId+itemId+actionType+eventTime) | 架构 M08-T01 |
