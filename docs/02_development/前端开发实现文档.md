## 二、核心代码实现

### 2.1 Axios 请求封装（统一响应处理）

**文件路径**：`src/api/request.js`

**功能**：创建 Axios 实例，配置请求/响应拦截器，统一处理后端 `Result<T>` 响应结构。

**核心逻辑**：

1. **请求拦截器**：
   - 自动生成/透传 `X-Trace-Id`（与后端 TraceIdFilter 对齐，全链路追踪）
   - `/admin/**` 路径自动附加 `X-API-Key` 管理员鉴权头

2. **响应拦截器**：
   - `code=0`：成功，返回完整响应
   - `code=400001`（召回为空）/ `400002`（排序降级）/ `400003`（Embedding不可用）：业务降级码，不弹错误，返回数据供页面自行处理
   - `code=200001/200003`：鉴权失败，提示并跳转
   - `code=600001`：限流，友好提示
   - 其他错误码：ElMessage 统一报错
   - HTTP 层错误：按状态码分类提示（429限流/504超时/503不可用/5xx服务器错误）

```javascript
// 响应拦截器核心逻辑（节选）
service.interceptors.response.use(
  (response) => {
    const res = response.data
    if (res.code === 0) return res
    // 业务降级码：不报错，返回数据
    if (res.code === 400001 || res.code === 400002 || res.code === 400003) return res
    // 鉴权失败
    if (res.code === 200001 || res.code === 200003) {
      ElMessage.error('登录已过期，请重新登录')
      router.push('/')
      return Promise.reject(new Error(res.message))
    }
    // 限流
    if (res.code === 600001) {
      ElMessage.warning('请求过于频繁，请稍后再试')
      return Promise.reject(new Error(res.message))
    }
    // 其他业务错误
    ElMessage.error(res.message || `请求失败 (code: ${res.code})`)
    return Promise.reject(new Error(res.message))
  },
  (error) => { /* HTTP层错误分类处理 */ }
)
```

### 2.2 推荐结果 Store（Pinia）

**文件路径**：`src/stores/recommend.js`

**功能**：管理当前推荐场景、用户ID、推荐结果、加载状态，封装推荐接口调用与行为上报。

**核心方法**：

| 方法 | 说明 |
|-----|------|
| `fetchRecommend(params)` | 获取推荐结果，支持 Mock 降级（真实接口失败自动切换 Mock 保证页面可用） |
| `switchScene(scene, extraParams)` | 切换场景并重新获取推荐 |
| `reportBehavior(behaviorData)` | 上报用户行为（点击/收藏等），自动填充 userId/scene/eventTime |

**关键设计**：
- Mock 降级机制：当 `VITE_USE_MOCK=false` 但真实接口请求失败时，自动降级到 Mock 数据并输出 warn 日志，保证演示页面始终可用
- 行为上报异步非阻塞：上报失败不影响用户体验，仅记录 console.error

### 2.3 推荐结果展示组件

**文件路径**：`src/components/RecommendResult.vue`

**功能**：统一展示 4 种场景的推荐结果，被首页/猜你喜欢/相关/搜索 4 个页面复用。

**交互逻辑**：
1. **加载状态**：8 个骨架屏卡片模拟加载
2. **空状态**：召回为空时展示 ElEmpty + 重新加载按钮
3. **结果元信息**：场景/A/B组/模型版本/候选数/总耗时 Tag 展示
4. **各阶段耗时折叠面板**：缓存/召回/特征组装/精排/重排/总计 6 项耗时明细（el-descriptions）
5. **物品卡片网格**：响应式 grid 布局（`repeat(auto-fill, minmax(220px, 1fr))`）

### 2.4 物品卡片组件

**文件路径**：`src/components/ItemCard.vue`

**功能**：展示单个推荐物品，点击时自动上报点击行为。

**交互逻辑**：
- 点击卡片 → 调用 `recommendStore.reportBehavior()` 上报 `actionType=click`，携带 `itemId`/`position`(排名)/`device`
- 排名前 3 名展示金银铜渐变色角标
- 召回通道标签按通道类型着色（itemcf蓝/tag绿/profile橙/hot红/es_text灰/es_semantic紫）
- 推荐分数展示在右上角蓝色 Badge

### 2.5 A/B 实验管理页面

**文件路径**：`src/views/admin/AbExperiments.vue`

**功能**：A/B 实验全生命周期管理，是管理后台最复杂的页面。

**核心交互**：

1. **列表筛选**：按实验名称模糊搜索 + 状态筛选
2. **新建/编辑弹窗**：
   - 表单校验：实验名称必填、流量比例必填、开始/结束时间必填
   - 实验组配置：动态增删实验组行，每组含组名/流量%/描述
   - 流量校验：实验组流量总和必须等于 100%，否则禁止提交
   - 编辑时 `configVersion` 自动 +1（与后端 M11-T01 约束对齐）
3. **状态机操作**：
   - draft → running（启动）
   - running → paused（暂停）
   - paused → running（恢复）
   - running/paused → ended（结束）
   - 所有状态变更操作均有 ElMessageBox 二次确认
4. **实验报告弹窗**：
   - 实验基本信息 Descriptions
   - 指标对比表格：指标名/对照组/实验组/提升率/P值/显著性
   - 结论建议 Alert：根据 CTR 的 P 值和 lift 方向自动生成（显著提升→建议全量发布；显著下降→建议终止；不显著→继续观察）

### 2.6 模型管理页面

**文件路径**：`src/views/admin/ModelManagement.vue`

**核心交互**：
- **激活校验**：点击激活时，前端先校验 `featureConsistencyPassed=true`，未通过则禁止激活并提示（与后端 M11-T02 约束对齐：模型激活前校验 feature_consistency_passed=1）
- **激活联动**：激活某模型时，自动将同类型其他 active 模型置为 inactive
- **质量门禁提示**：指标详情弹窗中展示该模型类型的 AUC 门禁要求（DeepFM≥0.80，XGBoost≥0.78）

### 2.7 用户画像页面

**文件路径**：`src/views/demo/UserProfile.vue`

**可视化实现**：
- **类目偏好**：横向进度条，按权重降序排列
- **标签权重**：标签云，按权重大小区分 Tag 尺寸和颜色
- **活跃时段**：24 小时柱状图（纯 CSS 实现，每小时一个柱子，高度与活跃度成正比）
- **融合标签**：深色 Warning Tag 突出展示

### 2.8 仪表盘页面

**文件路径**：`src/views/admin/Dashboard.vue`

**图表实现**：
- 使用 ECharts 5 + vue-echarts，按需引入（LineChart/PieChart/TitleComponent/TooltipComponent/LegendComponent/GridComponent），减小打包体积
- **请求量趋势图**：双 Y 轴折线图（左轴请求量，右轴延迟），平滑曲线 + 面积填充
- **召回通道饼图**：环形图（radius 40%-70%），图例右侧垂直排列

### 3.2 推荐接口对接详情

**接口**：`GET /api/v1/recommend`

**请求参数**：

| 参数 | 类型 | 必填 | 页面来源 | 说明 |
|-----|------|------|---------|------|
| scene | string | 是 | 路由场景映射 | home/guess/related/search |
| userId | string | 是 | DemoLayout 顶部输入框 | 用户ID，默认 u_10001 |
| itemId | string | related必填 | RelatedRecommend 页面输入框 | 相关推荐参考物品ID |
| keyword | string | search必填 | SearchRecommend 搜索框 | 搜索关键词 |
| pageSize | int | 否 | 各页面数量调节器 | 默认20，最大50 |
| device | string | 否 | 固定值 web | 设备类型 |

**数据渲染逻辑**：
1. 调用 `recommendStore.fetchRecommend(params)` → Axios GET 请求
2. 响应拦截器校验 `code`，成功后存入 `recommendStore.result`
3. `RecommendResult` 组件通过 getters 读取 `items`/`abGroup`/`modelVersion`/`candidateCount`/`duration`
4. 物品列表通过 `v-for` 渲染 `ItemCard` 组件
5. 各阶段耗时通过 `el-collapse` 折叠面板展示

**场景参数联动**：
- 路由变化时，`DemoLayout` 的 watch 自动同步 `recommendStore.currentScene`
- `related` 场景：页面提供 itemId 输入框，校验必填后才允许请求
- `search` 场景：页面提供搜索框 + 热门搜索词，回车或点击搜索按钮触发

### 3.3 行为采集接口对接详情

**接口**：`POST /api/v1/behavior`

**触发时机**：用户点击推荐物品卡片时自动触发。

**请求体构造**（`recommendStore.reportBehavior`）：
```javascript
{
  userId: recommendStore.userId,      // 当前用户ID
  itemId: behaviorData.itemId,        // 物品ID
  actionType: 'click',                 // 行为类型
  scene: recommendStore.currentScene,  // 当前场景
  eventTime: new Date().toISOString(), // 当前时间 ISO 8601
  extra: { position: rank, device: 'web' } // 扩展字段
}
```

**渲染逻辑**：行为上报为异步非阻塞，上报成功后 ElMessage 提示"已点击: xxx"，失败不影响页面（仅 console.error）。

### 3.4 用户画像接口对接详情

**接口**：`GET /api/v1/user/{userId}/profile`

**数据渲染逻辑**：
1. 页面 onMounted 时调用 `userProfileApi.getUserProfile(userId)`
2. 响应 data 包含 `longTerm`/`shortTerm`/`fusedTags`/`version`/`updatedAt`
3. 长期画像：
   - `categoryPreferences` → 横向进度条（按权重降序）
   - `tagWeights` → 标签云（按权重区分尺寸/颜色）
   - `activeHours` → 24小时柱状图
   - `activityLevel`/`pricePreference`/`registerDays` → 顶部 Tag
4. 短期画像：
   - `recentClickedItems`/`recentFavoritedItems` → 物品ID Tag 列表
   - `recentCategories` → 横向进度条
   - `recentActionCount` → Descriptions 统计
5. 融合标签：`fusedTags` → 深色 Warning Tag 云

### 3.5 热门物品接口对接详情

**接口**：`GET /api/v1/hot/items`

**请求参数**：`categoryId`（可选，类目筛选）、`limit`（默认20，最大100）

**数据渲染逻辑**：
1. Top 3 物品：突出卡片展示（金银铜渐变背景 + 皇冠/奖牌图标）
2. 4 名以后：el-table 表格展示（排名/名称/类目/价格/点击量/收藏量/热度分进度条）
3. 热度分计算：后端已计算（click×0.7 + favorite×0.3），前端直接展示

### 3.6 管理后台接口对接说明

管理后台接口（`/admin/**`）在请求拦截器中自动附加 `X-API-Key` 头进行管理员鉴权。

由于后端 M11 管理后台 API 在当前后端实现文档中标注为"未实现"，前端管理后台页面默认使用 Mock 数据（`VITE_USE_MOCK=true`）。当后端 M11 模块开发完成后，只需将 `VITE_USE_MOCK` 设为 `false`，前端 API 封装层已完全对齐后端接口契约，无需修改页面代码。

## 四、交互实现

### 4.1 表单校验

| 页面 | 表单 | 校验规则 | 实现方式 |
|-----|------|---------|---------|
| 相关推荐 | itemId输入 | 必填 | el-form rules + `required: true` |
| 搜索推荐 | 关键词输入 | 非空（trim后） | JS 手动校验 `!keyword.value.trim()` |
| A/B实验-新建 | 实验名称 | 必填 | el-form rules |
| A/B实验-新建 | 流量比例 | 必填 | el-form rules |
| A/B实验-新建 | 开始/结束时间 | 必填 | el-form rules |
| A/B实验-新建 | 实验组流量总和 | 必须=100% | JS 手动计算 `totalGroupPercent`，提交前校验 |
| 系统配置 | 配置值 | 非空 | JS 手动校验 `!row.configValue.trim()` |
| 缓存管理-前缀 | Key前缀 | 必填 | el-form rules |
| 缓存管理-Key | 具体Key | 必填 | el-form rules |

**校验失败处理**：
- el-form 校验失败：自动高亮错误字段 + 显示错误信息，阻止提交
- JS 手动校验失败：ElMessage.warning/error 提示，阻止后续操作

### 4.2 状态反馈

| 反馈类型 | 场景 | 实现方式 |
|---------|------|---------|
| 加载中 | 推荐结果加载 | `v-loading` 指令 + 骨架屏（el-skeleton animated） |
| 加载中 | 表格数据加载 | `v-loading` 指令 |
| 加载中 | 按钮提交 | `:loading` 属性（按钮内显示加载图标+禁用） |
| 操作成功 | 保存/激活/刷新等 | `ElMessage.success()` |
| 操作警告 | 校验失败/限流 | `ElMessage.warning()` |
| 操作失败 | 接口错误/网络异常 | `ElMessage.error()` |
| 危险操作确认 | 删除/结束实验/激活模型/刷新缓存 | `ElMessageBox.confirm()` 二次确认 |
| 空状态 | 召回为空/无数据 | `el-empty` 组件 + 操作按钮 |
| 进度反馈 | 特征一致性校验触发 | 弹窗 + el-progress 进度条 + 阶段提示文字 |

### 4.3 弹窗逻辑

| 弹窗 | 页面 | 触发 | 关闭逻辑 |
|-----|------|------|---------|
| 新建/编辑实验 | A/B实验管理 | 点击"新建实验"/"编辑"按钮 | 取消/确定按钮，`@closed` 重置表单 |
| 实验报告 | A/B实验管理 | 点击"实验报告"按钮 | 右上角关闭按钮 |
| 模型指标详情 | 模型管理 | 点击"指标详情"按钮 | 右上角关闭按钮 |
| 缓存注意事项 | 缓存管理 | 点击"注意事项"按钮 | 右上角关闭按钮 |
| 校验进度 | 特征一致性 | 点击"手动触发校验"并确认 | 进度100%后自动关闭（500ms延迟） |

**弹窗通用约束**：
- `:close-on-click-modal="false"`：禁止点击遮罩层关闭（防止误操作丢失表单数据）
- 表单类弹窗：`@closed` 事件中重置表单数据和校验状态
- 危险操作类：打开前先 ElMessageBox 确认，确认后才打开弹窗

### 4.4 异常处理

#### 4.4.1 HTTP 请求异常

统一在 Axios 响应拦截器中处理（见 2.1 节），按错误类型分类：

| 错误类型 | 处理方式 |
|---------|---------|
| 业务错误（code≠0） | ElMessage 显示后端 message，Promise.reject |
| 业务降级（400001/400002/400003） | 不报错，返回数据供页面处理 |
| 鉴权失败（200001/200003） | 提示 + 跳转首页 |
| 限流（600001/HTTP 429） | 友好提示"请求过于频繁" |
| 超时（HTTP 504 / ECONNABORTED） | 提示"请求超时" |
| 服务不可用（HTTP 503） | 提示"服务暂不可用" |
| 服务器错误（HTTP 5xx） | 提示"服务器错误，请联系管理员" |
| 网络异常 | 提示"网络异常，请检查网络连接" |

#### 4.4.2 业务异常

| 场景 | 处理方式 |
|-----|---------|
| 推荐召回为空（code=400001） | RecommendResult 组件展示空状态 + 重新加载按钮 |
| 排序降级（code=400002） | 正常展示结果，message 中说明实际使用模型 |
| 模型激活-特征一致性未通过 | 前端拦截，ElMessage.error 提示，不发请求 |
| 实验组流量总和≠100% | 前端拦截，ElMessage.error 提示 |
| 配置值为空 | 前端拦截，ElMessage.warning 提示 |
| 真实接口失败（非Mock模式） | recommendStore 自动降级到 Mock 数据 + console.warn |

#### 4.4.3 全局异常兜底

- Vue 全局错误处理：`app.config.errorHandler`（可在 main.js 中配置，当前依赖 Element Plus 组件内部处理）
- Promise 未捕获异常：浏览器控制台输出，不影响页面渲染

**Nginx 配置示例**：
```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /usr/share/nginx/html;
    index index.html;

    # 前端路由 history 模式 fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /admin/ {
        proxy_pass http://backend:8080;
    }

    location /actuator/ {
        proxy_pass http://backend:8080;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

| 架构要求 | 前端实现方式 | 对应章节 |
