## 四、联调问题

### P-01【严重·流程不通】行为上报→推荐缓存失效链路未实现

| 项目 | 内容 |
|-----|------|
| 问题编号 | P-01 |
| 严重程度 | 严重（阻断核心闭环） |
| 影响链路 | L2 行为采集 → L1 推荐主链路 |
| 可复现性 | 100% 可复现 |

**现象**：用户点击物品上报行为后，该用户的推荐结果缓存不会失效，后续推荐仍返回旧缓存数据，无法体现行为对推荐的实时影响。

**根因定位**：
- `BehaviorController.collect()` 仅调用 `behaviorCollectorService.collect(event)`，未注入 `RecommendCacheService`
- `MockBehaviorCollectorService.collect()` 仅生成 eventId 并记录日志，未调用 `cacheService.invalidateByUser(userId)`
- `RecommendCacheService` 已提供 `invalidateByUser(userId)` 方法（架构文档 6.5 节约定"行为触发失效"），但无任何调用方

**复现步骤**：
1. 请求 `GET /api/v1/recommend?scene=home&userId=test_invalidate&pageSize=2`，记录返回的 items
2. 上报行为 `POST /api/v1/behavior`（userId=test_invalidate）
3. 立即再次请求相同推荐接口
4. 预期：缓存已失效，重新计算推荐（可能返回不同结果）
5. 实际：返回缓存中的旧结果，items 完全一致

**涉及文件**：
- `controller/BehaviorController.java`
- `service/behavior/MockBehaviorCollectorService.java`
- `service/cache/RecommendCacheService.java`（方法已存在，未被调用）

### P-03【中等·异常处理】未实现路径返回 500 而非 404

| 项目 | 内容 |
|-----|------|

**现象**：访问不存在的 API 路径（如 /admin/ab/experiments）时，返回 HTTP 500 "服务内部错误"，而非预期的 HTTP 404 "资源不存在"。


### P-04【中等·异常处理】JSON 请求体格式错误返回 500 而非 400

| 项目 | 内容 |
|-----|------|
| 问题编号 | P-04 |
| 严重程度 | 中等 |
| 影响范围 | POST /api/v1/behavior（所有 @RequestBody 接口） |

**现象**：当行为采集接口收到格式错误的 JSON 请求体时，返回 HTTP 500 "服务内部错误"，而非 HTTP 400 "参数格式错误"。

**根因定位**：`HttpMessageNotReadableException`（Jackson JSON 解析失败）未被 `GlobalExceptionHandler` 专门处理，落入兜底 Exception 分支。

### P-06【轻微·契约不一致】召回为空时 code 不会是 400001

| 项目 | 内容 |
|-----|------|
| 问题编号 | P-06 |
| 严重程度 | 轻微（当前 Mock 环境不触发） |
| 影响接口 | GET /api/v1/recommend |

**现象**：文档约定召回为空时返回 `code=400001`（HTTP 200，业务降级码），但实际代码中 `RecommendationFacade.buildEmptyResponse()` 返回普通 `RecommendResponseDTO`，Controller 统一用 `Result.success()` 包装，导致 code 始终为 0。

**根因定位**：
- `RecommendationFacade.recommend()` 在召回为空时调用 `buildEmptyResponse()` 返回 DTO
- `RecommendController.recommend()` 无条件 `return Result.success(response)`
- 未通过 `Result.degraded(ErrorCode.RECALL_EMPTY, response)` 返回降级码

**当前状态**：MockRecallService 始终返回 250 候选，不会触发空召回，因此该问题在当前环境不可见。生产环境替换真实召回服务后可能触发。

### P-07【轻微·错误信息】BusinessException 自定义 message 被忽略

| 项目 | 内容 |
|-----|------|
| 问题编号 | P-07 |
| 严重程度 | 轻微 |
| 影响范围 | related/search 场景必填校验等所有 BusinessException |

**现象**：`RelatedStrategy.validate()` 抛出 `BusinessException(PARAM_MISSING, "related 场景需要 itemId")`，但响应中 message 为 ErrorCode 枚举的默认值"缺少必填参数"，自定义 message 丢失。

**根因定位**：`GlobalExceptionHandler.handleBusinessException()` 调用 `Result.fail(e.getErrorCode())`，该方法使用 `errorCode.getMessage()` 而非 `e.getMessage()`。

**日志 vs 响应对比**：
- 日志：`业务异常: code=100002, message=related 场景需要 itemId`
- 响应：`{"code":100002,"message":"缺少必填参数"}`
